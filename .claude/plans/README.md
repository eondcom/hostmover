## 작업 규칙 (모든 지시서 공통)

각 문서 §0~§1 에 적혀 있지만 반복해 둔다.

1. **문서에 없는 판단은 하지 말고 질문한다.**
2. **Phase 단위로 커밋**하고, 각 Phase 의 `DoD` 를 통과해야 다음으로 간다.
3. `cargo test` 전부 통과 / `cargo build --release` 경고 없음.
4. 주석·UI 문자열·커밋 메시지는 **한국어**.
5. 자격증명을 소스·테스트에 넣지 않는다.
6. **대시보드는 자동으로 SSH 를 쏘지 않는다** — 버튼을 눌렀을 때만. (대시보드 계열 전체)
7. 실서버 접속은 사람이 한다. 테스트는 스크립트 문자열 검증 + `bash -n` 까지만.

## 이미 구현된 것을 건드릴 때

아래는 검증을 마친 동작이다. **바꾸지 말 것**:

- `domain_issue()` 가 `local_code`(LH)를 참조하지 않는다
  — `curl --resolve` 는 vhost 가 없어도 기본 vhost 가 200 을 준다
- 결과는 `Done{ok:true}` 에서만 커밋하고 실패 시 이전 캐시를 유지한다
- 이상 건수는 `domain_issue()` 하나로 집계한다(개별 카운터 합산 아님)
- 삭제 스크립트는 `v-delete-*` 를 쓰고 웹루트를 직접 `rm -rf` 하지 않는다
- 보호 계정 거부가 Rust 검증과 원격 셸 **양쪽**에 있다
