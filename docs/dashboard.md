# 시작 대시보드

Hostmover는 잠금 해제 직후 대시보드를 표시합니다. 설정의 **시작 화면**에서 마지막 화면 복원으로 바꿀 수 있습니다.

## 즉시층과 서버층

첫 화면은 로컬 암호화 저장소의 고객·도메인 정보와 마지막 사이트 스캔 캐시만 사용합니다. 앱을 열거나 대시보드로 이동하는 것만으로는 SSH가 실행되지 않습니다. VPN이 끊겼거나 서버가 다운된 때에도 첫 화면이 SSH 타임아웃을 기다리지 않게 하기 위한 구조입니다.

서버 헬스의 **새로고침**과 도메인 헬스의 **점검**을 사용자가 눌렀을 때만 각각 SSH를 한 번 실행합니다. 성공한 결과는 저장되며 다음 실행에서도 즉시 보입니다. 조회가 실패하면 이전 캐시를 유지합니다.

## 지표 읽기

- 등록 현황: 휴지통이 아닌 고객 수와 그 고객에게 등록된 도메인 수입니다.
- 서버 사이트: 마지막 전체 사이트 스캔의 CMS 분포, 파일·DB 용량, 업데이트 필요 수입니다.
- 서버 헬스: 부하, 메모리, 실제 블록장치의 최대 디스크 사용률, 서비스와 PHP-FPM 상태, HestiaCP 계정·도메인 수, 자동 감시 설치 상태입니다.
- 도메인 헬스: 웹루트, 서버 로컬 응답, 공개 응답, DNS A 레코드, 인증서 만료일까지를 한 번에 점검합니다. 최대 8개 도메인을 병렬 처리합니다.

각 카드의 `N분 전`, `N시간 전`, `N일 전`은 현재 상태가 아니라 **마지막으로 성공한 조회 시점의 캐시**를 뜻합니다. 예를 들어 `3시간 전 기준`이면 화면의 숫자도 3시간 전 점검 결과입니다. 서버 헬스와 도메인 헬스는 별도 버튼으로 따로 조회하므로 두 캐시 시각이 서로 다를 수 있습니다. 장애 대응이나 변경 작업 직후처럼 현재 값이 필요할 때는 해당 카드의 새로고침 또는 점검을 직접 실행하십시오.

자동 조회를 하지 않는 이유는 SSH 한 번에 수 초가 걸리고 여러 서버·도메인은 수십 초 이상 걸릴 수 있기 때문입니다. VPN 미연결이나 서버 장애 상태에서 자동 조회하면 매번 타임아웃까지 앱이 멈춘 것처럼 보입니다. 따라서 첫 화면은 로컬 캐시로 즉시 그리고 원격 조회는 사용자 동작으로만 시작합니다.

도메인 헬스는 최대 8개를 병렬로 검사하며 각 네트워크 요청의 타임아웃은 8초입니다. 도메인 100개는 서버와 네트워크 상태에 따라 약 2분 걸릴 수 있습니다.

## 도메인 정상 판정

DNS가 이 서버를 가리킬 때만 공개 HTTP 응답을 주 지표로 사용합니다. 공개 응답이 2xx 또는 3xx이고 웹루트가 있으며 인증서가 만료되지 않았거나 14일 넘게 남아 있으면 정상입니다.

다음은 이상으로 표시합니다.

- DNS A 레코드가 없거나 다른 서버를 가리킴
- DNS가 이 서버를 가리키지만 공개 응답이 없거나 4xx/5xx임
- 웹루트가 없음
- 인증서가 만료됐거나 만료까지 14일 이하임

로컬 응답(`LH`)은 참고값일 뿐 정상 판정에 사용하지 않습니다. `curl --resolve`로 서버 자신을 조회하면 요청한 가상 호스트가 없어도 기본 가상 호스트가 200을 반환할 수 있기 때문입니다. 따라서 `DNS=none`인데 `LH=200`인 경우도 정상으로 보지 않습니다.

## 자동 감시 표시

디스크·트래픽 자동 감시는 관련 cron 파일의 존재만 확인합니다. 설치되지 않았으면 대시보드가 회색 안내를 표시하며, 다른 감시 기능에 의존하지 않습니다. 디스크 감시의 마지막 실행 시각이 확인되고 36시간을 넘으면 경고합니다.

디스크 감시 시각은 서버가 자신의 타임존으로 계산한 epoch 값을 사용합니다. 앱이 서버의 로컬 시각을 KST라고 추측하지 않으므로 UTC 등 다른 타임존의 서버에서도 경고 시간이 어긋나지 않습니다. 구버전 캐시에 epoch가 없을 때만 기존 날짜문자열을 KST로 해석하며, 시각이 전혀 없으면 감시 중단으로 단정하지 않습니다.
